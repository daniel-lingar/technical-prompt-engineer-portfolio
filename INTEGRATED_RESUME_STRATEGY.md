# Integrated Resume Strategy: The WRH Project System

## Core Conclusion

The repositories are **one connected body of work**, not eight unrelated projects. Together, they show a repeatable method for taking complex, source-heavy material from early notes and archives through structured writing, plain-language translation, curriculum architecture, implementation documentation, versioned publication, and public-facing static sites.

> **Recommended positioning:** Documentation Systems & Curriculum Architect with public evidence of source control, research organization, plain-language translation, structured learning design, and static-web publication.

For AI-operations applications, use a narrower variant of the same truthful positioning: **Technical Documentation and Evaluation Systems Builder**. The prompt-engineering portfolio should be treated as an interpretive layer over the broader work: it makes the transferable methods—constraints, evidence boundaries, structured outputs, quality checks, and reproducible review—explicit for AI evaluators. It does **not** prove paid RLHF or model-training employment, so do not claim that experience.

Before sending recruiters to the system, consolidate the public record around a consistent reviewer journey.

1. **Correct cross-account links.** The Capitol Contracts repository still lists related resources under the `Mave9055` account while the public evidence being presented is under `daniel-lingar`. Either correct each link or explain the relationship and source-of-truth clearly. [4]
2. **Clarify canonical status.** The manuscript repositories currently distinguish a working source, a canonical release, and an archive; make the same labels unmistakable in each README and pin one `START HERE` file for the overall ecosystem. [3] [6] [7]
