## Cross-Repository Narrative

The repositories represent a connected body of work, not unrelated side projects. The core is a public, non-clinical education and implementation system that moves from lived-experience source material and structured archives into plain-language frameworks, curriculum delivery, reviewer-facing documentation, and public web publication. The work consistently emphasizes versioning, canonical-source control, source provenance, clear scope boundaries, user-oriented navigation, and reproducible publishing workflows.

## Evidence by Workstream

### 1. Structured Curriculum and Implementation System

The **WRH Master Curriculum** repository documents a four-part educational architecture with **77 source Markdown session records**, a searchable static session explorer, generated session catalog, facilitator-oriented materials, scope boundaries, and GitHub Pages deployment. The related **Capitol Contracts LLC** repository positions the work as non-clinical psychoeducational curriculum, implementation tools, facilitator materials, pilot documentation, and plain-language pattern-recognition systems for recovery, veteran-support, reentry, peer-support, public education, and institutional partners.

The reviewed public curriculum site verifies these materials as a coherent reader and implementation experience: it provides orientation, curriculum navigation, searchable session access, pilot-material entry points, clear safety boundaries, no-disclosure learning guidance, facilitator stop criteria, and measurement-oriented pilot language.

### 2. Plain-Language Translation and Public Education

The **Rescue Boat** repository is a locked 10-article public edition and digital education platform. It uses a Markdown-based article system, React/Vite frontend, static deployment, canonical-lock policy, checksums, verification scripts, and accessible reader-oriented publication to translate complex survival, shame, freeze, avoidance, and addiction patterns into non-clinical plain language.

The reviewed public site explicitly presents this as part of the wider WRH system and directs readers to the related WRH curriculum and Capitol Contracts implementation repositories. It supplies multiple reader paths, an article index, a lock version, and an explicit non-clinical scope boundary.

### 3. Source, Editorial, and Publication Provenance

The two **From the Storm to the Fire** repositories separate canonical long-form manuscript materials from historical production artifacts. The canonical source contains organized chapters, source and recovery folders, multiple compiled export formats, a master index, and publication materials. The working-manuscript repository records structural revisions, developmental drafts, appendices, notes, and revision history. The book-production repository is explicitly retained as an archived revision-provenance workspace with design assets, build scripts, exports, and workflow materials.

### 4. Research Archive and Evidence Handling

The **Horner Archive** contains a public Civil War microhistory project with a dossier, source folders, people records, field documents, images, maps/KML, transcripts, corrections, grant-readiness material, and scripts. The content demonstrates archival organization, documentary traceability, and a public-facing research-site structure.

### 5. Prompt and Evaluation Portfolio Layer

The **Technical Prompt Engineer & AI Evaluation Specialist** portfolio packages prompt schemas, constrained evaluator formats, edge-case stress testing, root-cause diagnostic prompts, SOP synthesis patterns, a copy-ready application profile, curriculum architecture, and a public GitHub Pages portfolio. It presents the underlying work as transferable evidence for structured prompt evaluation, documentation, and asynchronous systems roles.

## Important Accuracy Boundaries

1. The public record supports claims about repository architecture, documentation systems, public publishing, curriculum structure, source organization, and prompt/evaluation artifacts. It does not independently prove paid employment as an AI trainer, formal RLHF contractor, or model evaluator.
2. The Capitol Contracts documentation states Daniel Bret Lingar should be described as **Director of Operations / Technical Lead / Curriculum Development Support** rather than owner, CEO, President, or final-control authority. It also states the company is not SDVOSB-certified.
3. The projects include sensitive memoir and trauma-related subject matter. For a broad technical resume, present these as evidence of **plain-language systems design, source-to-publication workflows, curriculum architecture, and structured documentation**; do not foreground personal or clinical content unless the role is specifically relevant.
4. The Capitol Contracts README contains related-project links pointing to a different GitHub account (`Mave9055`). This cross-account inconsistency should be corrected or clearly explained before relying on that repository as a primary recruiter-facing evidence source.
